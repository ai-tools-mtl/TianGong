# 有益效果三段式对比

## 核心铁律

**每个有益效果必须由三个部分构成，缺一不可：**

1. **现有技术如何** —— 引用「现有技术缺点」章节的具体短板
2. **本申请如何** —— 本方案的具体做法（对应某个技术特征 / 模块）
3. **因此获益** —— 与现有方案的量化或定性差异

**禁止用一句话概括**（如"本发明提高了效率"），那是无效效果。

## 不及格 vs 合格范例

### ❌ 不及格（单句概括）

> 本发明通过优化调度算法，提高了任务处理效率，降低了资源浪费。

问题：未指出与哪个现有技术对比、未给量化依据、无对应技术特征。

### ✅ 合格（三段式）

> **优点 1（对应缺点 1，由技术方案 §3.3 的限频重排模块实现）：降低调度抖动。**
>
> 现有的轮询调度器（见 §1.2 缺点 1）按固定周期触发任务，在突发负载下会出现相邻任务间隔过短导致的资源争用。
>
> 本申请的限频重排模块对每个任务维护最小触发间隔阈值，到达的任务先入等待队列，间隔未满足时延迟释放。
>
> 与现有方案相比，本方案将相邻任务最小间隔从不可控的 0（可能瞬时并发）收敛到受控的下界 $k$，调度复杂度由 $O(|S|)$（全量扫描）降为 $O(\log|S|)$（堆顶取最优先）。

## 量化依据分级（禁止跳级）

效果描述中的"快 / 低 / 高"必须有依据，按以下优先级提供，**禁止跳级、禁止臆测绝对值**：

| 优先级 | 依据类型 | 示例 |
|--------|----------|------|
| 1（最优） | 原型实测数据 | "在 1000 任务负载下实测，平均延迟从 120ms 降至 35ms" |
| 2 | 公开文献引用 | "据 [文献 X]，现有方案复杂度为 O(n²)" |
| 3（兜底） | 算法复杂度分析 | "本方案复杂度 O(k)，现有方案 O(|S|)" |

**禁用：** 无依据时臆测"约 10μs""快 500 倍""提升 90%"等绝对数值。无数据就用复杂度对比（$O(k)$ vs $O(|S|)$）或数据量对比（KB 级 vs GB 级）。

## 删主观夸大词

以下词在有益效果中出现时必须替换为量化或定性事实：

| 禁用 | 替代 |
|------|------|
| 首次提出 / 业界首创 | 改为"区别于 [现有方案 X] 的……"（需指出区别点） |
| 大幅 / 显著 / 极大 | 给出具体倍数、百分比或复杂度对比 |
| 完美 / 彻底 / 完全 | 改为可验证的范围（"在该工况区间内……"） |

技术论证（如某假设的证明、某密码学性质的推导）**不入有益效果**，应放在技术方案章节，效果章节只引用结论。

## 自检清单

- [ ] 每个优点都有"现有→本方案→获益"三段，无一勺烩
- [ ] 每个优点标注对应哪个缺点（引用 §1.2）和哪个技术特征（引用 §3.x）
- [ ] 量化依据未跳级，无臆测绝对值
- [ ] 无主观夸大词
