# 天工 PC 端 UI 设计契约（grill 结论）

> 本文档由 `/grill-me` 设计访谈产生（2026-07-14），记录天工前端从「单栏阅读型」重构为「工作台型」的 10 个关键决策及其连锁影响。
> **实施记录详见：** `plans/2026-07-14-plan8-ui-redesign.md`
> **约束场景：** PC 端（≥1280px），不含移动端/平板

---

## 锚点总览

GitHub/Figma 工具感 · 亮色默认（暗色可选）· 墨色产品态 + AI 紫专属 · 紧凑三栏 + 用户可折叠 · UI 用系统栈 / 正文用思源黑体 · 全量覆盖（地基 + 项目工作区 + 四个非项目页）

---

## 一、骨架契约

| 维度 | 决定 | grill 问题 |
|---|---|---|
| **整体形态** | 工作台型：左侧栏 + 主工作区满宽（GitHub/Figma 锚点） | Q2 |
| **全局导航** | 顶部栏承载：工作台 / 模板 / 管理 / 设置 | Q3 |
| **左栏** | **项目级**，只在 `projects/[id]/*` 出现，放章节大纲 / 版本 / 评审 | Q3 |
| **主布局** | 项目内页 = **紧凑三栏**：左大纲 / 中编辑器 / 右 AI 对话 | Q4 |
| **折叠策略** | 左右栏可用户手动收/展，状态存 localStorage | Q5 |
| **目标最小宽度** | 支持 1280px（紧凑三栏按比例缩，不自动折叠） | Q5 |

### 连锁决定（隐含，实施时必须遵守）

1. **左栏宽度**：项目级 + 紧凑三栏 → 左栏固定 **240px**，可收起到 **56px** 竖条（章节序号 + 状态点）。
2. **右栏宽度**：AI 强存在 → 右栏 **360px**，可收起到 0（彻底隐藏，浮动按钮呼出）。
3. **中编辑区**：被三栏压缩，正文不再用 `max-w-5xl`(1024px)，而是 **flex 自适应 + 内容软上限 `max-w-3xl`(768px)**（专利段落可读宽度）。
4. **顶部全局栏**：高度 **h-14 (56px)**，左对齐 logo + 全局入口，右侧主题切换 + 用户区。满宽（不沿用 `max-w-5xl`）。

## 二、皮（视觉语言）契约

| 维度 | 决定 | grill 问题 |
|---|---|---|
| **默认主题** | **亮色优先**，暗色可选（跟随系统 / 手动切换） | Q8 |
| **画布基调** | 冷灰底（墨色系，hue 240 蓝灰方向），GitHub/Figma 工具感 | Q6/Q7 |
| **产品态颜色** | 墨色 ink：主按钮、选中、链接、进度——接近黑、不用品牌色 | Q7 |
| **AI 专属色** | **紫**（亮底靛紫 `oklch(0.48 0.19 285)` / 暗底亮紫），严格只出现在对话气泡、AI 建议、✨ 图标、渐变光晕上 | Q6/Q7 |
| **品牌点缀** | 无独立品牌色——天工 = 墨色 + AI 紫，性格靠"AI 元素被点亮"来定义 | Q6 |

### 连锁决定

5. **圆角**：亮色 + 工具感 → `--radius: 0.5rem (8px)`，按钮/输入框用 `sm (4-6px)`，卡片用 `lg (8px)`，**不用**大圆角（那会变 Notion/飞书风）。
6. **紫色用法约束**：亮底上紫做 **fill 时克制**（仅 AI 对话气泡淡紫底、AI CTA 按钮）、做 **glow 时高调**（AI 正在生成时的光晕动画）。绝不用在普通链接/选中态。
7. **语义状态色**（非品牌色，独立体系）：
   - `--success` 绿：已确认章节、已解决问题、得分提升
   - `--warning` 琥珀：待改进、得分下降
   - `--info` 蓝：进行中状态点
   - `--destructive` 红：删除、错误
8. **暗色主题**：亮色优先，但 `.dark` 变量必须全套配齐（用户可能切），紫色在暗色下改用亮紫（`oklch(0.7 0.2 285)`）+ 更强 glow。

## 三、字体契约

| 场景 | 字体栈 | grill 问题 |
|---|---|---|
| **UI（导航/按钮/标签）** | 系统栈：`PingFang SC, Microsoft YaHei, ...` + 西文 Geist Sans | Q9 |
| **正文 / 编辑器 / 预览 / 评审** | **思源黑体 Noto Sans SC**（Web 字体，全设备一致） | Q9/Q10 |
| **数字/代码** | Geist Mono | — |

### 连锁决定

9. **思源黑体加载策略**：用 `next/font/google` 的 `Noto_Sans_SC`，`weight:['400','500','700']`、`subsets:['latin']`、`preload:false`（中文字体体积大不 preload）、`display:'swap'`、`variable:'--font-zh'`。
10. **字体作用域隔离**：仅挂在 `.prose / .tiptap / [data-review-content]` 类上，UI（导航/按钮）保持 Geist + 系统栈保响应——**避免全站加载中文字体导致首屏卡**。
11. **选择思源黑体的理由**：业界标杆、字形全、开源免费、GitHub 中文 fallback 同源、零气质违和（不似阿里普惠体带"电商味"）。详见 grill Q10。

## 五、token 命名契约（globals.css）

新增的 token（亮/暗各一套）：

```
--ai                  AI 主紫（气泡边框、图标、CTA）
--ai-foreground       AI 元素上的前景文字
--ai-muted            淡紫底（AI 气泡背景）
--ai-muted-foreground 淡紫底上的次级文字
--success / --success-foreground
--warning / --warning-foreground
--info    / --info-foreground
--font-zh             思源黑体变量
```

语义 token（shadcn 标准，已存在但改值）：`--background`(冷白) / `--foreground`(墨) / `--primary`(墨) / `--muted`(冷灰) / `--border`(冷灰) / `--ring`。

## 六、grill 决策依据（为什么不是别的）

这部分记录每个抉择的**否决项**，未来若想反悔需先回应这些理由。

### Q2 为什么不保留单栏？
天工用户长时间在编辑器 + AI + 大纲 + 评分间切换，单栏阅读型（max-w-5xl 居中）会频繁滚动/切换，工作台型三栏同屏才是"工具"。

### Q4 为什么 AI 不浮动/全屏？
AI 是产品一等公民（"AI 驱动"定位）。浮动球/抽屉打断写作流，全屏切换有摩擦。常驻右栏让 AI 和写作同屏，是核心卖点。

### Q7 为什么产品态不也用紫？
紫色当主 CTA 在专业工具里偏轻、不够沉稳，专利客户可能觉得不正式。墨色管操作、紫只管 AI，层次最分明（GitHub + AI 外挂调性）。

### Q8 为什么不暗色默认？
专利文本几万字技术文档，长文写作场景下深色视觉疲劳更高。亮色优先 = 专业耐写。AI 紫光晕在亮底用深靛紫（不廉价），放弃 Cursor 那种深色炫感换耐写。

### Q9 为什么不全站用 Web 字体？
编辑器实时输入用 Web 字体会有延迟感。UI 用系统栈保响应、正文用 Web 字体保一致，是双优解而非妥协。

## 七、不在本契约范围

- 移动端/平板响应式（PC ≥1280px 唯一目标场景）
- 后端 API / 业务逻辑改动
- 新功能、i18n
- 动画系统（除 AI 光晕外不引入）

未来若需扩展到移动端，Q5（折叠策略）的三选项（优雅降级/比例缩放/用户控制）需重新抉择，三栏契约在窄屏物理上不可持续。
